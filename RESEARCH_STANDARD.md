# SIRP 2.0 — revised Python/library-first research standard

This project-local revision adopts the user's approved Python/PyTorch approach and supersedes earlier C++ and manual-backpropagation requirements. It does not claim external certification or conformance to an independently verified publication. The original standard text was not supplied; this document records the approved revision and retained requirements.

1. **Established implementations.** Reuse maintained detector implementations and pretrained weights. Do not implement neural-network components or backpropagation from scratch. Record upstream implementation, version/commit, weight identity, license, and citation before use.
2. **Attribution and provenance.** Record primary papers, official documentation, dataset licenses, download origins, and access dates in `docs/sources.csv`. Attribute adapted code and distinguish sourced facts from project decisions. Never fabricate sources.
3. **Immutable splits.** Before experiments, version dataset manifests, split assignments, content identities/checksums, label mappings, and split-generation logic/seed. Prevent near-duplicate and same-part/acquisition leakage where metadata allows. Never silently change a split; issue a new version and disclose it.
4. **Protected test evaluation.** Use training/validation data for model, threshold, tiling, and hyperparameter choices. Freeze the protocol before final test evaluation. Log test access; disclose repeated test use and any resulting limits. Do not tune on test outcomes.
5. **Recorded configurations and seeds.** Every run gets a unique `run_id`, resolved configuration, seeds for relevant libraries/workers, source commit and dirty-state record, dataset/split identities, model/weight identities, environment/dependency versions, hardware, and timestamps. Document nondeterminism rather than promising determinism from seeds alone.
6. **Fair comparisons.** Compare whole-image inference, tiled inference, and a higher-resolution whole-image control. Hold dataset splits, baseline weights/training, evaluation protocol, hardware, and postprocessing constant where possible. Record changed resolution, tile geometry/overlap, boundary handling, duplicate-box merging, confidence/NMS settings, effective pixel and compute budgets, latency, and peak VRAM. Report differences that cannot be controlled. Freeze detection metrics, IoU thresholds, coordinate mapping, and timing protocol before evaluation.
7. **Honest results.** Label unstarted work, failed runs, exploratory findings, and uncertainty explicitly. Report detection/localization quality and resource cost, relevant repeats/variability, limitations, and negative findings. Never invent results or compare unmatched settings as if controlled.
8. **Recoverable artifacts.** Put all run outputs under `experiments/<run_id>/`. Version small configurations, manifests, metadata, and summaries; keep datasets, weights, predictions, logs, and large outputs outside Git. Record durable storage locations and checksums for excluded artifacts needed for recovery; verify retrieval before claiming recoverability. Do not commit credentials or private data.
9. **Environment evidence.** Check model/framework/Python/driver/CUDA/GPU compatibility before installation or version selection. Record the actual environment after validation; create a lock only from a real resolved environment. Package import alone does not establish training or experiment reproducibility.
